# 评测

> 评测的目标不是证明"我们很强"，而是让"有没有退步"变成一件可以当场回答的事。
> 所以这里的每一项都写成可复跑的命令，以及明确的"它不测什么"。

## 1. 三层评测

| 层 | 入口 | 规模 | 测什么 | 不测什么 |
|---|---|---|---|---|
| 契约层 | `backend/selftest.py` | 176 个断言 | 模块契约、边界条件、跨层一致性 | 报告写得好不好 |
| 规划层 | `backend/mrbench.py` | 8 题 | 问题类型路由、MECE 树、因果假设是否成立 | 取证质量、结论正确性 |
| 判定层 | `backend/calibrate.py` | 8 正 + 8 反 | 核验器假阳性率、真阳性率、置信上界 | 通用场景下的真实 FPR |

三层解决三个不同的问题，**不能互相代替**。特别是：`selftest` 全绿不代表报告可信，它只代表"代码没坏"。

## 2. 契约层：`selftest.py`

```bash
cd backend
python selftest.py
```

特点：

- **完全离线**：不联网、不调用模型，检索与 LLM 全部 mock；
- **确定性**：同样的代码永远同样的结果；
- **覆盖"跨层一致性"**：同一个数字在报告、审计包、前端返回值三处必须相同；同一个定义在文档与代码里必须同源；
- **缺东西就 SKIP，不伪装成 PASS**：缺第三方依赖、缺内部材料（真实报告、探针、材料清单）的项记为 `⏭`，不计入通过也不计入失败。克隆环境下的基线是 **81 通过 / 95 跳过 / 0 失败**；在完整开发环境里，跳过项会真正执行。

典型用例：干净版报告里不允许出现评测痕迹；审计包的 `claims.csv` 行数必须等于结论数；闸门计数必须与正文附录一致；来源位不允许写入内部产物名称。

新增机制时，规则是：**先写断言，再写实现**。否则"机制上线"只是一句自我声明。

## 3. 规划层：MR-Bench（轻量版）

`mrbench.py` 的 8 个问题覆盖三类：

- **exploratory**（该不该进、有什么机会）→ 期望产出议题树；
- **descriptive**（市场规模、竞争格局）→ 期望产出统计描述与来源结构；
- **causal**（为什么放缓、价格是否影响采购）→ 期望产出 H1–H3 假设与反证方向。

对每题做确定性回归：路由是否正确、MECE 是否覆盖、因果题是否真的生成了假设而不是套模板。它不跑全量 LLM，因此**测不出报告质量**，只测"规划层有没有退化"。

## 4. 判定层：核验器校准

```bash
cd backend
python calibrate.py            # 跑一次并存档
python calibrate.py --no-save  # 只看结果
python calibrate.py --show     # 读现有存档
```

样本设计：8 条正例（应判 support）、8 条反例（绝不能判 support）。反例覆盖数字冲突、主体张冠李戴、口径范围、逻辑跳跃等类型。

输出：

```
严格 FPR    反例被判 support 的比例
宽松 FPR    反例被判 support 或 partial 的比例
TPR         正例被判 support 的比例
上界        单侧 95% 置信上界（Clopper–Pearson）
```

当前读数：严格 FPR **0.0%**、TPR **100%**、上界 **31.2%**。

**正确读法**：8 条反例零事件，只能支撑"真实 FPR 大概率低于 31.2%"。任何"我们的误判率是 0"的表述都是过度解读，报告里不允许出现。

每次修改 `core/entailment.py` 的判定提示词后必须重跑，并记录 `judge_prompt_fp`。不同指纹的校准结果不可横比。

## 5. 可复现性

一次运行的"可复现"，在这个项目里被拆成四个独立的东西：

| 维度 | 标识 | 含义 |
|---|---|---|
| 代码 | `engine_version` | `core/version.py` 单一出处 |
| 提示词 | `prompt_set` | 15 条提示词正文的哈希 |
| 假设 | `assumption_set` | UE 9 项 + 测算 6 项输入的规范化哈希 |
| 判定 | `judge_prompt_fp` | 核验器判定提示词指纹 |

**只有四项都相同的两次运行，才有资格横比。** 这解释了为什么同一个版本号下可能得到两套不同的单位经济——算术是确定的，但假设是模型每轮挑的 L5 估算。

## 6. 当前不测的东西

- 没有公开榜单成绩，也没有和商业产品做同题盲测；
- 没有真人用户样本，因此不报"满意度""付费意愿"；
- 没有多语言评测；
- 没有对"结论是否正确"做金标准标注——这件事需要领域专家，当前只有"结论是否有支撑"这一层。

把这些写出来，是为了避免把"机制完整"误读成"结论正确"。
