# 路线图

> 排序标准：**先修会让结论出错的东西，再修让人看得见的东西，最后才是做大。**
> 已完成项不写在这里，见 git history。

## P0 · 正确性（会让报告出错）

- [ ] **来源位守卫（R12 扩展）**：来源位只接受外部可核对象（域名 / 机构 / 文号），命中内部产物名一律降级为"待核"。
- [ ] **时效门接入判定**：数据期距研究时点 >3 年不得进入现状证据位；同一数据点重复填入 ≥3 章报"证据集中度"。
- [ ] **同族多值聚类**：把"同一指标不同措辞"归并后再比较，当前只抓"同指标名 + 多值"。
- [ ] **域守卫**：门店型单位经济模型不得套用到非门店业态；输入与本报告同题口径冲突 >30% 时阻断。
- [ ] **R13 角色分类**：区分"决策阈值"与"市场统计量"，统计量只报不拦，避免把描述性中位数当止损线。

## P1 · 可运维性（会让人踩坑）

- [ ] **前端组件化**：按「四区 + 八抽屉」拆分 `App.jsx`，先抽 `components/`，再抽状态管理。
- [ ] **持久化**：任务从内存迁到 SQLite/Postgres，支持重启恢复与多任务并发。
- [ ] **鉴权与配额**：单用户 → 多用户，加入 API Key 与用量隔离。
- [ ] **调用台账闭环**：把 ⑧⑨⑩ 三对（决策链 ↔ 台账 ↔ 路由 ↔ 注册表）接上，消除"各说各话"。
- [ ] **CI 完整化**：当前只跑 lint + 冒烟；补 `selftest.py` 的分层运行与报告导出快照测试。

## P2 · 评测与资产（决定长期上限）

- [ ] **MR-Bench 扩容**：4 题型 × 5 领域，20–30 题，带标注与失败标签。
- [ ] **指标血缘库**：把"同一指标的历史取值 + 口径 + 来源"沉淀成可查询的资产，而不是每次重搜。
- [ ] **机构可信度档案**：机构名 ↔ 出版物 ↔ 域名 ↔ 历史准确率。
- [ ] **跨期回测**：对历史报告做"今天还站得住吗"的复核，输出判断保质期。
- [ ] **校准样本扩充**：补"发布日期晚于模型知识截止"这类正例，避免核验器错怪官方发布。

## 明确不做

- **不做"全网爬虫"**：来源数量不是护城河，可核验性才是。
- **不做"AI 自动下结论"**：Go/No-Go 必须由人确认，系统只负责把代价与不确定性摆出来。
- **不把赛事名次写进产品叙事**：能力以代码与可复跑结果为准。
- **不做假数据演示**：模拟数据必须显著标注，且不进主 demo。

## 版本纪律

- 判据只在版本之间改，一次只改一类；
- 改判据必须同时更新：规则说明、阴性对照、已落盘报告的影响范围；
- 封版后新发现进入下一版本，不回改本版读数。
