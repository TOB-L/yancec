# ADR 0002：决策完整性闸门只降不升

## 背景

闸门最初的语义是"评估交付状态"，既能降级也能升级。实际使用中出现一个风险：当报告被判定为"证据不足"时，只要再补一段解释，就可能被重新判回"可以行动"——闸门变成了说服工具。

## 决定

闸门只能把交付状态往更保守的方向推：

```
Go → Validate → No-Go
```

永远不能反向。判定结果、命中位置、未阻断原因全部写入报告顶部横幅与审计包。

## 后果

- 闸门不会"洗白"一次本该被否决的交付；
- 代价是可能过度保守：一些本可放行的报告会被降级。接受这个代价，因为误放行的成本高于误拦截；
- 闸门不修改正文数字，只改变交付口吻与状态，避免"系统替我改数"的责任模糊。
