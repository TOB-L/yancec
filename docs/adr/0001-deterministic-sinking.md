# ADR 0001：计算下沉到确定性模块

## 背景

早期版本让模型直接生成 TAM/SAM/SOM、CAGR、盈亏平衡等数字。实测发现两个问题：

1. 同一道题两次运行给出不同的数（采样不稳定）；
2. 模型会在算术上"圆场"——当输入参数互相矛盾时，它倾向于写一句解释把矛盾抹平，而不是报错。

## 决定

所有可计算量由 `core/` 的确定性模块计算，模型只负责：

- 选择用哪个模型/口径（并说明理由）；
- 解释结果的含义；
- 在参数缺失时提出假设（必须标注为 L5 估算）。

模型**不允许**修改引擎输出。正文若声称"修正/校准了引擎值"，规则层直接判 R8。

## 后果

- 同一组输入永远得到同一组数，可复算；
- 灵活性下降：新指标需要写代码，不能靠提示词"顺手加一个"；
- 参数仍需模型挑选，因此引入 `assumption_set` 哈希（见 ADR 0004）来区分"同版本不同假设"的运行。
