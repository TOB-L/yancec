# 审计与核验流水线

> 这份文档描述"为什么这个报告可以被追问"。每一层都写了两件事：**它证明什么**，以及**它不证明什么**。
> 后者比前者重要——把边界写清楚，才不会有下一层替上一层背书。

## 1. 五道核验各自回答一个问题

| 层 | 实现 | 回答的问题 | 不证明 |
|---|---|---|---|
| ① 来源资格 | `source_quality.py` `source_registry.py` | 这个来源**有没有资格**说这句话？ | 不证明这句话是对的 |
| ② 文本支撑 | `entailment.py` | 来源原文**是否支持**这条结论？ | 不证明来源本身真实 |
| ③ 证据配对 | `evidence_matrix.py` | 这条结论是否按**要求的方式**交叉验证过？ | 不证明两侧独立（同源转载会伪装成两家） |
| ④ 数字一致 | `rule_lint.py` R1/R5/R10/R11 | 同一个指标在不同章节是否**自相矛盾**？ | 不证明采信值正确 |
| ⑤ 结论状态 | `confidence.py` | 现有证据足以支撑到哪一档？ | 不证明没漏掉关键证据 |

设计纪律：**五层不许互相冒充**。例如"引文核验通过率 96%"只说明第②层，不能拿来当"报告可信度"，报告里也不允许这样写。

## 2. 规则层（R1–R15）

规则层是纯函数，不调用模型，同样的输入永远同样的输出。它的目标不是"全面"，而是**把已经踩过的坑钉死**。

| 规则 | 判定 | 典型病案 |
|---|---|---|
| R1 | 同一关键指标多值跨度 >20% | 单店年营收 42.6 万 vs 123.5 万 |
| R2 | 未来年份被当作已发生事实 | 「据国家统计局 2027 年数据」 |
| R3 | 术语/缩写全报告未定义 | EBITDA、LTV 直接使用 |
| R4 | 匿名来源 + 具体数值 | 「行业数据显示 41%」 |
| R5 | 正文算术与换算不符（>4pct） | 32 元写成「日均收入的 97%」（实约 29%） |
| R6 | 0–10 打分无方法学/样本 | 「价敏度指数 7.8（满分 10）」 |
| R7 | 来源资格错配 | 用 gov.cn 给某企业门店数背书 |
| R8 | 自称修正引擎输出 / 当众择一 | 「引擎显示 106 亿，此处取 88 亿」 |
| R9 | 同一数字挂两个量纲 | 月 vs 日混用造成假冲突 |
| R10 | 同一数字两个分母 | 「家/10 万人」与「家/万人」混写 |
| R11 | 行动建议低于自算盈亏平衡线 | 建议 150 杯/日，BEP 为 205 杯/日 |
| R12 | 来源位写入内部产物 | 「来源：本次调研数据」而调研尚未执行 |
| R13 | 决策阈值低于报告自己算的盈亏平衡线 | 止损线设在亏损线以下 |
| R14 | 同一增速挂在两个基期上 | 「较 2022 年 +142%」与「较 2023 年 +142%」 |
| R15 | 市场规模嵌套倒挂 | 下沉 SAM > 全国 SAM |

新增规则时必须同时提供一条**阴性对照**：一段不该被命中的文本。只写阳性用例的规则，会在真实报告里常态误报，最后被人忽略——被忽略的 linter 比没有 linter 更糟。

## 3. 决策完整性闸门

### 3.1 它改变什么

```
PASS   无高风险项
WARN   有发现，但不在决策区
BLOCK  高风险发现落入决策区 → 交付状态强制降为 Validate
```

「决策区」是报告里读者会据以行动的部分：执行摘要、决策判定、行动建议、成本测算、关键假设。

### 3.2 只降不升

闸门只能把交付状态往更保守的方向推，不能反向。原因是**升级会制造洗白通道**：只要闸门有权把 Validate 改回 Go，它就会成为新的说服工具，而不是检查工具。

### 3.3 它不修改数字

闸门不改写正文里的任何一个数。它做的是：把"不该以可以直接行动的口吻交付"这件事说出来，并留下阻断清单。改不改，是人来决定。

### 3.4 留痕要求

每条阻断必须带：命中的规则、所在章节、原文片段、风险等级、是否可修。缺任何一项，闸门结论不可对外引用。

## 4. 可复算审计包

### 4.1 结构

```
audit_bundle/
├── README.md        三步复算指引
├── manifest.json    元数据 + 每个文件 SHA-256
├── rules.md         本次运行判定规则（从常量导出，不手写）
├── claims.csv       结论：状态 / 置信度 / 独立域名数 / 来源 / 数据期 / 口径
├── sources.csv      来源：层级 / 分组 / URL / 检索词 / 核验判定
├── raw/             检索层原始返回（仅截断长度，不加工）
├── compute.py       标准库：重算 CAGR / 同比 / 来源占比
└── verify.py        标准库：重探 URL 存活 + 重判结论状态
```

### 4.2 三条契约

1. **脱离本项目可跑**：`compute.py` / `verify.py` 不 import 任何本仓库模块，只用 Python 标准库。
2. **规则不漂移**：`rules.md` 从运行时常量导出。改代码不改文档，导出件会跟着变；改文档不改代码，导出件不会变。
3. **原始记录不加工**：`raw/` 存的是检索层真实返回。审计包的说服力来自"你可以不用信我"。

### 4.3 `verify.py` 做什么

- 重新请求 `sources.csv` 里每个 URL（HEAD，失败回退 GET），频率 ≥1s/host；
- 把"仍可访问 / 已失效 / 域名变更"与 `claims.csv` 声明的状态对账；
- 输出差异表：**声明 vs 复算**。

它不判断内容对错，只判断"你引用的那页还在不在、你说它支撑的结论是否仍成立到可核对的程度"。

## 5. 自一致性层（登记表，不是穷举）

系统会自检"自己的产物是否互咬合"，目前登记了 11 对：

| # | 对 | 现状 |
|---|---|---|
| ① | 来源位 ↔ 外部可核来源 | 已落码（R12） |
| ② | 同实体多值 ↔ 单一采信值 | 已落码（R1/R10） |
| ③ | 数据期 ↔ 使用位置 | 只展示，未阻断 |
| ④ | 决策输入 ↔ 同题口径 | 已落码（R13） |
| ⑤ | 判据 ↔ 打印列 | 已落码（`pair_ok`） |
| ⑥ | 值 ↔ 文本来源 | 已落码（边际量守卫） |
| ⑦ | 定义 ↔ 定义 | 已落码（L1–L5 同源锁） |
| ⑧ | 决策链 ↔ 调用台账 | 未接线 |
| ⑨ | 源层级标注 ↔ 注册表 | 未接线 |
| ⑩ | 路由命中 ↔ 台账调用 | 未接线 |
| ⑪ | 自陈计数 ↔ 自陈计数 | 部分（遗漏层已闭合） |

**这张表是登记表，不是本跑的触发清单。** 未接线的对会明确写"未接线"，不写成"已覆盖"。这是刻意的：藏起来是雷，写出来是分。

## 6. 核验器校准

`backend/calibrate.py` 用固定样本测核验器：

```
正例 8 条（应判 support）
反例 8 条（绝不能判 support）
输出：严格 FPR / 宽松 FPR / TPR / 单侧 95% 上界
```

当前结果：严格 FPR **0.0%**，TPR **100%**，单侧 95% 上界 **31.2%**。

正确读法：**8 条反例零事件，只能说明"真实 FPR 大概率低于 31.2%"，不能说明"FPR 是 0"。** 报告里必须同时给点估计与上界；只报点估计，等于用样本量换一个好看的数字。

修改 `core/entailment.py` 的判定提示词后必须重跑校准，并记录 `judge_prompt_fp`。没有指纹的校准结果不参与跨版本比较。

## 7. 三种"没做成"的记账

| 记号 | 含义 | 是否计入"跳过" |
|---|---|---|
| `empty` | 通道正常，返回空 | 否 |
| `planned_skip` | 本轮计划不使用该源族 | 是（单独计） |
| `degraded` | 通道不可用，已切换 | 否（计入降级） |

三者混记，就会出现"向 0 个源发起请求"却产出几十条证据的账。台账必须能回答：**这条证据是哪一次调用、哪个通道、什么检索词拿到的。**

## 8. 当前边界（诚实清单）

- 第③层"双源配对"能识别"两侧存在"，但不能识别"两侧是否同源转载"；
- 第③层不判断"要求验证对"是否真的满足，只打印要求与实际，由第⑤层判定；
- 数据期规则目前只展示、未阻断过期数据；
- ⑧⑨⑩ 三对未接线，台账与决策链仍可能各说各话；
- 规则的量纲白名单仍以 元/杯/月/% 为主，`家/万人`、`占比` 类覆盖不全；
- 校准样本只有 16 条，不能支撑"通用场景下 FPR<1%"这类结论。

这些不是"以后再说"，而是**当前版本的真实状态**。改动它们会改变已落盘报告的读数，因此按版本节奏推进，不在一版里同时动多条判据。
